1需求背景

在正确的时间，以正确的方式，将有价值的信息传递给正确的用户，促使其采取正确的行动（打开 App、查看行情、进行交易等），同时避免过度打扰。

核心设计原则：高优先级通知（爆仓预警、强平通知、登录异常）不受任何频控与免打扰限制，确保用户在关键时刻能第一时间获知风险；其余类型通知遵循频控规则，保障体验。

3行情异动

① 目标价提醒：用户在 App 内自主设置目标价，到价即推，每个价位仅触发一次，后台无需配置阈值
② 大幅涨跌：系统统一监控所有已选标的，按后台配置的阈值触发，每标的每日最多推 N 次

6后台配置说明

6.1 推送消息列表

后台以统一列表形式管理所有 14 种推送类型，分四个分类展示（信息通知 / 行情异动 / 平台公告 / 最新活动），支持：

  • 逐类型开关控制（全局生效，覆盖用户个人设置）
  • 编辑各类型的用户端标题 / 内容模板，变更次日生效
  • 配置各类型跳转目标页面
  • 配置推送渠道（iOS / Android / 站内信）

6.2 行情阈值配置

配置项默认值说明
大幅上涨触发阈值5%24H涨幅达到此值时触发大幅上涨推送
大幅下跌触发阈值5%24H跌幅达到此值时触发大幅下跌推送
极端行情加推阈值10%涨跌幅超过此值时可在当日额外推送一次
每标的每日最多触发1 次同一标的在同一天的推送上限，极端加推不计入
监控标的列表-后台维护需监控的交易对列表，支持单独开关

6.3 频控管理

以下三类不受任何频控 & 免打扰限制：⚠️ 爆仓预警   💥 仓位已强平   🔐 登录异常
配置项默认值说明
单用户每日 Push 总上限20 条 / 天超出上限后静默处理，站内信仍正常入账
免打扰默认时段22:00 – 08:00用户未自定义时使用平台默认值；高优通知不受限
订单成交合并推送每笔实时可配置为 N 分钟内合并一条推送
返佣入账推送频率每笔实时可配置为日汇总推送
活动通知每日上限2 条 / 天单用户每天最多收到 N 条活动推送

6.4 手动推送（运营）

运营可在后台配置并发送平台公告 / 活动通知，流程如下：

  1. 填写 通知类型（活动通知 / 平台公告 / 新币上线）
  2. 填写 Push 标题（最多 30 字）和 Push 内容（最多 100 字）
  3. 配置 跳转位置（活动落地页 / 交易页 / 自定义 URL）
  4. 选择 目标用户群体（全体 / 新注册 / 活跃 / 高净值 / 未激活 / 自定义 UID）
  5. 选择 发送时间（立即发送 / 定时发送）
  6. 预览 iOS 锁屏效果 后确认发送

6.5 推送记录 & 统计

支持查看历史推送记录及分类数据统计：

  • 每条记录显示：发送时间、通知类型、目标用户群体、发送量、触达率、点击率、状态
  • 支持按类型、时间范围筛选，支持导出报表
  • 分类统计：各推送类型的月度发送量、平均触达率、平均点击率、用户关闭率

8补充说明 & 待确认事项

以下事项需与开发确认：
  1. 爆仓预警触发条件：当前文案中 {gap} 表示距强平百分比，触发阈值（如距强平价 ≤ N% 时触发）需与后端确认具体数值
  2. 大幅涨跌计算周期：目前定义为 24H 涨跌幅，若有需要可扩展至 1H / 4H 等周期
  3. 站内信 fallback 规则：用户未授权推送时是否自动降级为站内信，需确认 fallback 范围（建议所有重要通知均 fallback）
  4. 订单成交合并推送：合并规则（时间窗口 / 单次最多合并 N 条）需产研对齐
  5. 多设备处理：同一用户登录多台设备时，推送是否发所有设备还是仅最近活跃设备
  6. 登录异常判断逻辑：新设备 / 异地登录的判断维度需与安全团队对齐
