1需求分析

1.1用户分析

  • 目标用户：持有并使用多个本人账号的活跃用户——包括现货/合约分账号操作者、机构或工作室的多账号运营人员、以及同时管理个人号与家庭代管号的用户。
  • 用户特点：切换频次高、对操作效率敏感；账号多为邮箱/手机号注册，需在列表中快速辨识「哪个是哪个」。
  • 核心诉求：① 免登切换，不重复输密码/2FA；② 一眼辨识账号（昵称 + 脱敏登录方式）；③ 安全——列表不暴露完整账号信息、当前账号不被误删。
  • 外部反馈渗透率、诉求占比：待运营补充调研数据。

1.2竞品分析

2产品概述

2.1产品逻辑

账号切换核心是登录会话（token）的切换：设备本地保存最多 25 个已登录账号的会话凭证，切换即在本地会话间切换并刷新用户态，无需重新输入密码/2FA。会话过期的账号需重新登录激活。

主流程（状态流转）

[My Account] —点右上角切换icon→ [Switch Account 列表] ├─ 点未过期的其他账号 ──→ 切换成功 → 刷新用户态 → 返回 [My Account] ├─ 点当前账号(Current) ──→ 无动作 ├─ 点过期账号(Expired) ──→ 弹「重新登录」确认 → [登录页] → 成功后回列表(已激活) ├─ 点右上角 Edit ────────→ [删除态] │ ├─ 点其他账号垃圾桶 → 二次确认弹窗 → Confirm → 移除该账号 │ ├─ 当前账号：无垃圾桶，不可删除 │ └─ 点 Done ───────→ 退出删除态 └─ 点底部 Add ───────────→ [登录页] → 登录成功 → 加入列表(不登出当前账号) （列表满 25 个时 Add 置灰不可点）

账号会话状态机：active（可切换） ⇄ current（当前登录）；active/current → expired（会话过期）；expired → active（重新登录激活）；任意非 current 状态 → removed（删除）。

2.2功能信息架构

My Account（我的账号） ├─ Profile / Nickname / UID / Fee Schedule ├─ [右上角] 切换账号入口（icon）───────────→ Switch Account └─ [底部] Log Out（退出当前账号，二次确认） Switch Account（切换账号） ├─ [导航右上] Edit（进入/退出删除态） ├─ Current Account（分组） │ └─ 当前账号行：头像 + 昵称 + 脱敏登录方式 + ✓勾选 ├─ Other Accounts（分组） │ └─ 账号行 × N：头像 + 昵称 + 脱敏登录方式 [ + Expired标 / 删除态垃圾桶 ] ├─ 计数提示：n / 25 └─ [底部] Add a new account（满25置灰） / Done（删除态）

3.3原型及说明

原型截图由 PM 从 账号切换-App原型.html 截取插入；以下以 MECE 原则拆解每屏逻辑。

3.3.1　My Account · 切换入口

📱
【原型截图占位】My Account 页，右上角切换账号 icon

需求说明：

  1. 页面顶部导航右上角新增切换账号入口，以 icon 呈现（双向箭头 swap 语义），点击进入 Switch Account 页。
  2. 页面主体保留 Profile / Nickname / UID / Fee Schedule 信息行；UID 仅在此页展示且可复制（R12：切换列表不展示 UID）。
  3. 底部保留 Log Out（整行按钮），点击二次确认后退出当前账号（R10）。切换入口不再放在底部。

3.3.2　Switch Account · 账号列表（多账号）

📱
【原型截图占位】Current Account + Other Accounts 分组列表

需求说明：

  1. 分组结构（R11）：Current Account 分组置顶，仅当前账号一行，带 ✓ 绿色勾选 + 金色头像描边；其下 Other Accounts 分组，展示其余全部账号。
  2. 账号行信息（R12）：头像（昵称首字母）+ 昵称 + 脱敏登录方式；不展示 UID。
  3. 脱敏口径（R14）：
    • 邮箱：前 3 位 + *** + 完整 @尾缀，如 rhy***@gmail.com；
    • 手机：区号 + 前 3 位 + *** + 后 3 位，如 +86 134***234、+1 516***797；8 位短号同规则 +65 812***567；星数固定 3 颗，不随长度变化。
  4. 切换交互（R2/R3/R4）：点其他未过期账号 → 免登切换成功 → 返回 My Account 并刷新用户态，轻提示「已切换到…」；点当前账号无动作；点过期账号见 3.3.4。
  5. 底部：Add a new account 按钮 + n / 25 计数提示。
单账号态：仅一个账号时，只展示 Current Account 分组一行，无 Other Accounts 分组；底部照常展示 Add。

3.3.3　Switch Account · 删除态

📱
【原型截图占位】删除态（垃圾桶 + Done）与二次确认弹窗

需求说明：

  1. 点导航右上角 Edit（笔）进入删除态：其他账号行右侧显示垃圾桶图标；底部按钮由 Add 变为 Done（R6）。
  2. 当前账号不可删除（R8）：删除态下当前账号不显示垃圾桶，仍保留 Current 标识；退出当前账号只能走 My Account 的 Log Out。
  3. 过期账号可删除（R9）：Expired 账号在删除态显示垃圾桶，可清理。
  4. 点垃圾桶 → 弹二次确认「Confirm deletion?」（R7）→ 点 Confirm 移除该账号；点 Cancel 取消。
  5. 点 Done 退出删除态，恢复正常列表。

3.3.4　登录页 · 添加账号 / 过期重登

📱
【原型截图占位】Add Account 登录页

需求说明：

  1. 添加账号（R5）：底部 Add a new account → 进登录页，登录成功后该账号加入切换列表，且不登出当前账号；返回列表并轻提示「账号已加入切换列表」。
  2. 25 上限（R1）：账号数达 25 时 Add 按钮置灰不可点，底部提示「已达账号上限 25 个，如需添加请先删除」。
  3. 过期重登（R4）：点击 Expired 账号弹「Session expired，是否重新登录？」，确认后进登录页；登录成功后该账号状态由 expired → active 并回到列表。

3.4边界 Case（服务评审）

编号场景系统行为 / 用户提示
B1仅剩 1 个账号（当前账号）且进入删除态当前账号无垃圾桶，无可删项；用户只能 Done 退出。（当前账号永不可删 → 不会出现「删空」）
B2切换目标账号时其会话恰好过期切换失败，将该账号置为 Expired 并提示「登录已过期，请重新登录」，引导至登录页。口径待研发确认
B3账号数已达 25，仍点 AddAdd 置灰不可点；若通过其他入口触发，toast「已达 25 个上限，无法继续添加」。
B4删除二次确认弹窗打开时点击遮罩等同 Cancel，关闭弹窗不删除。
B5极短号码（国家码后不足 6 位）前 3、后 3 可能重叠。主流手机号 ≥7 位不触发；若涉虚拟小号需追加兜底。待确认

B7被禁用账户尝试切入不可切入；列表呈现方式（隐藏/置灰/Expired 类比）待确认。

6API 相关调整

以下为本需求涉及的接口调整方向（唯一允许出现实现层内容的章节），具体协议由前后端评审确定。

接口能力说明
获取可切换账号列表返回设备本地已保存账号：账号标识、昵称、登录方式类型（邮箱/手机）、脱敏后展示串、会话状态（current/active/expired）、头像。
脱敏建议由后端统一下发展示串，避免各端口径不一致（前端不接触完整账号信息）。
切换账号（换会话）以目标账号本地会话凭证换取有效登录态；会话失效时返回过期错误码，前端置该账号为 Expired。
添加账号（登录并入列）登录成功后将新会话凭证追加到本地账号列表，不影响当前账号会话；需服务端下发上限（25）供前端置灰判断。
删除账号（移除会话）移除指定账号的本地会话凭证与列表项；禁止删除当前账号（服务端与前端双重校验）。
上限与计数账号数上限 25 建议由服务端配置下发，前端不写死，便于后续调整。
安全提示：多账号会话凭证在设备本地的存储与加密、切换时的 2FA/风控策略，需与安全/风控组对齐；异常多账号聚集需纳入风控识别。

✓PRD 自检

  • 内容防污染：本需求不涉及第三方内容注入；账号信息列表脱敏展示，前端不接触完整账号串。
  • 资产平账：仅切换登录会话，不发生任何资产变动，无平账风险（Checklist #2/#3=N）。
  • 风控漏洞：当前账号不可删（双重校验）、过期会话需重登、删除二次确认，已覆盖误操作与越权路径。
  • 受限地区：切换功能无地区限制，但受限地区账号的登录/交易拦截沿用既有策略——需风控确认是否对多账号聚合有额外识别要求。
  • KYC 门槛：添加账号走标准登录，KYC 拦截沿用登录既有逻辑——需确认未完成 KYC 的账号能否加入切换列表。
  • 待人工确认项：B2 切换时过期口径、B6 重复添加、B7 禁用账户呈现、Checklist #7 Web 端是否同步、#8 禁用账户呈现、B5 极短号码兜底。
