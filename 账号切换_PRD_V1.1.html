01一、需求分析

1.1 需求背景

用户常在多个本人账号间往返操作（现货 / 合约分账号、机构或工作室多账号运营、家庭代管号等）。当前切换必须先登出再重新登录、重复输入密码与 2FA，操作繁琐且易误操作。主流交易所（Binance）已提供多账号免登快捷切换能力。本需求对齐该能力，在保证账号安全的前提下提升多账号用户的操作效率与留存。

1.2 用户分析

  • 目标用户：持有并高频使用多个本人账号的活跃用户——现货/合约分账号操作者、机构/工作室多账号运营、个人号 + 代管号并用者。
  • 用户特点：切换频次高、对效率敏感；账号多以邮箱/手机号注册，需在列表中快速辨识「哪个是哪个」。
  • 核心诉求：① 免登切换，不重复输密码/2FA；② 一眼辨识账号（昵称 + 脱敏登录方式）；③ 安全——列表不暴露完整账号信息、当前账号不被误删、长期不用的账号需重新验证。
  • 外部反馈渗透率、诉求占比：待运营补充调研数据。

02二、产品概述

2.1 产品逻辑

账号切换的核心是登录会话（token）的本地切换：设备本地保存至多 25 个已登录账号的会话凭证，切换即在本地会话间切换并刷新用户态，无需重新输入密码/2FA。会话有有效期——账号连续 7 天未登录（无活跃）即判定过期（R15），需重新验证后方可再次使用。

2.2 功能架构

My Account（我的账号） ├─ Profile / Nickname / UID（可复制）/ Fee Schedule ├─ [右上角] 切换账号入口（icon）──────→ Switch Account └─ [底部] Log Out（退出当前账号，二次确认） Switch Account（切换账号） ├─ [导航右上] Edit（进入 / 退出删除态） ├─ Current Account（分组） │ └─ 当前账号行：头像 + 昵称 + 脱敏登录方式 + ✓ 勾选 ├─ Other Accounts（分组） │ └─ 账号行 × N：头像 + 昵称 + 脱敏登录方式 ［ Expired 标 / 删除态垃圾桶 ］ ├─ 计数提示：n / 25 └─ [底部] Add a new account（满 25 置灰）／ Done（删除态） 登录页（Add 新增 / 过期重新验证共用）

05五、API 相关调整

以下为本需求涉及的接口调整方向（唯一允许出现实现层内容的章节），具体协议由前后端评审确定。

5.1 C 端接口

接口能力说明
获取可切换账号列表返回本地已保存账号：账号标识、昵称、登录方式类型、脱敏后展示串、会话状态（current/active/expired）、头像、最近活跃时间。脱敏建议由后端统一下发展示串，前端不接触完整账号信息。
切换账号（换会话）以目标账号本地会话凭证换取有效登录态；会话失效（含超 7 天）返回过期错误码，前端置该账号 Expired。
添加账号（登录并入列）登录成功后将新会话追加到本地列表，不影响当前账号会话；服务端下发上限（25）供前端置灰判断。
删除账号（移除会话）移除指定账号本地会话与列表项；禁止删除当前账号（服务端 + 前端双重校验）。
过期账号重新验证点击 Expired 账号走全量登录（密码 + 2FA），验证成功后刷新该账号会话有效期、状态回 active。

5.3 定时任务

任务说明
7 天未登录过期判定各账号最近登录/活跃时间超过阈值（默认 7 天）即标记为 Expired，在切换列表中不可直接切换、需重新验证。计时口径由前端定义（前端本地掌握各账号会话时间）；后端配合返回会话有效性并支持阈值配置。
